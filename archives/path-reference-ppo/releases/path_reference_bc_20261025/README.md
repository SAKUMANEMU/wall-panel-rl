# 五个静态障碍物：RRT 路径 + BC 关节跟踪器

本目录是独立发布包，基于仓库原有代码新增文件，不替换原来的模型、配置或 README。发布权重为 `tracker_bc.zip`；运行时先用原有 `ClassicalController` 做 IK/RRT 规划，再由学习到的跟踪器根据下一关节路点输出 7 维动作。因此这是一套**规划辅助的控制方案**，不是端到端避障 PPO，也不能把此权重直接用于旧的 70 维观测接口。

## 方法和训练数据

环境保持原有五个随机静态障碍物配置、整机械臂及夹持板的碰撞检查、关节限位和 20 Hz 控制。每次测试现场重新规划路线；测试场景文件中的预计算参考路径已移除。规划失败时不让专家动作接管。

跟踪策略的输入是原有 70 维观测加归一化的下一关节路点 7 维，输出 7 维关节控制动作。每个关节有一个正增益和偏置；行为克隆只训练这 14 个系数，速度项保持 0，critic 和动作标准差保持冻结。动作在执行前按关节限位留出 0.01 rad 裕度。策略定义见 [`src/wall_panel_rl/rl/waypoint_tracking.py`](../../src/wall_panel_rl/rl/waypoint_tracking.py)。

`training/teacher_arrays.npz` 收录 100 条成功的五障碍物教师轨迹，共 5,945 个状态动作对。BC 以 seed 61、batch size 256、Adam 学习率 0.003 训练 2,000 次更新。所发布权重的训练集 MSE 约为 `1.37e-13`；各关节增益接近 1，说明主要学会了复现现有路点伺服控制律。`training/bc_61.json` 和 `training/bc_73.json` 保存两个种子的训练摘要。训练数据全部成功不等于随机场景都可规划，也不代表学习策略自身会规划。

之后做了两组 PPO 试验，seed 61 和 73 各 10,000 环境步。每组使用 4 个环境、每环境 250 步 rollout、batch size 100、每次更新 3 个 epoch、学习率 `1e-5`、clip `0.05`、target KL `0.005`，动作标准差冻结为 `0.02`、entropy 系数为 0。奖励采用原任务奖励，并对当前路点距离缩短量添加 `2 × 距离缩短量 / 最大关节增量`；路点游标在计算奖励后更新。PPO 没提高成功率或速度，因此**最终选择 BC 检查点，新增 PPO 步数为 0**。这表示该权重已经过 BC 训练，并非未经训练。试验摘要在 `evaluation/ppo_61.json`、`evaluation/ppo_73.json`；两组 PPO 权重未随包发布。

## 已有验证

同一组 90 个五障碍物静态场景，包含原验证 30 个及两组回归场景各 30 个：

| 方案 | 成功 | 碰撞 | 超时 | 规划失败 |
| --- | ---: | ---: | ---: | ---: |
| 原纯策略模型 | 57/90 | 29 | 4 | 不适用 |
| 前一版纯策略候选 | 59/90 | 27 | 4 | 不适用 |
| RRT + 普通路点跟踪 | 89/90 | 0 | 0 | 1 |
| RRT + 0.01 rad 限位裕度的普通跟踪 | 89/90 | 0 | 0 | 1 |
| RRT + 本次 BC 跟踪器 | **89/90** | **0** | **0** | **1** |

有规划路径的 89 条都跟踪成功，但全流程成功率为 89/90，不能说 100%。BC 跟踪器相对原纯策略模型提升明显，**相对 RRT + 普通跟踪没有成功率或速度收益**：两者成功任务的平均控制步数约 60.02。两个 BC 种子和两个 PPO 试验在这组场景上都为 89/90。另有 20 个无障碍物对齐场景全部成功。逐场景记录、汇总和场景清单见 `evaluation/`，其中 `manifest.json` 指向包内的 110 个场景。`media/comparison.mp4` 是 seed 81009 的示例视频：左侧原纯策略碰撞，右侧本次跟踪器成功；它不是统计检验。

## 当前问题

1. seed `121019` 的 IK 成功，但 RRT 在 15 秒预算内没有找到路径；两次不同随机状态的重试仍失败。尚不能断言该场景在几何上无解。该故障发生在规划层，继续训练现有跟踪器不能直接消除。
2. 跟踪器依赖实时 RRT 路径；其 77 维输入与旧纯策略 70 维输入不同，不能直接替换旧权重。
3. 现有验证场景在研发中多次被使用；预留的 100 个独立随机种子 `211000–211099` 尚未执行，因此 89/90 不是独立泛化成绩。
4. 目前只验证了静态五障碍物和配置中的物理、噪声条件。尚无动态障碍物、明显扰动或真实机械臂验证，也没有证据证明 PPO 比普通路点跟踪更有价值。

## 建议的后续工作

1. 先对 seed `121019` 做 IK/RRT 诊断：区分无解与采样预算不足，检查整机械臂、夹持板、墙体和障碍物的碰撞约束，并记录候选路径与失败原因。改动规划器后复测全部 90 个场景，尤其是碰撞和限位。
2. 冻结代码和模型，再跑预留的独立 100 个五障碍物场景。建议门槛为 90/90 回归不下降、独立集 100 条完整报告，之后再做长时间压力测试。普通跟踪与 BC 必须共用场景和规划路径比较。
3. 若希望 PPO 提升系统性能，先设计能区分普通伺服与学习控制的扰动、传感噪声或模型误差测试，明确奖励和提升指标，再训练并在独立场景验收。当前没有依据继续盲目增加 PPO 步数。

## 使用和复现

在仓库根目录按原仓库 `README.md` 安装环境。以下命令均从仓库根目录运行；依赖原仓库的 URDF、环境与 RRT 代码。

```bash
# 运行包内示例场景，输出 JSON 结果
python releases/path_reference_bc_20261025/run_tracker.py

# 随机生成一个新的静态五障碍物场景
python releases/path_reference_bc_20261025/run_tracker.py --random --seed 211000

# 重新训练 BC，必须指定一个尚不存在的输出文件
python releases/path_reference_bc_20261025/train_bc.py --seed 61 --output /tmp/tracker_bc_retrained.zip

# 用包内场景重新比较普通跟踪与 BC；完整清单含 90+20 条
python releases/path_reference_bc_20261025/evaluate.py --output /tmp/path_reference_eval.json
```

复训输出与发布 ZIP 不保证逐字节一致；比较动作误差与场景成绩。`SHA256SUMS.txt` 记录发布文件校验值，`metadata.json` 记录权重 SHA256、接口和训练规模。`evaluate.py` 仅比较普通和 BC 跟踪；原纯策略和 PPO 的既有结果保存在 `evaluation/`。
