# Existing code, libraries, and asset attribution

## Project-specific implementation

The submitted environment, observation/action construction, reward shaping, custom policy adapters, reference recovery, IK/RRT integration, timed scheduling, predictive execution control, experimental scripts, and recording/replay integration are project implementation. The source module names are retained for checkpoint compatibility. `PROVENANCE.json` identifies the selected checkpoint and original working-copy snapshot. `MANIFEST.sha256` records the packaged file contents.

The project does not claim to implement the following third-party frameworks or robot assets from scratch. Libraries are installed through the pinned environment; their binaries are not vendored into this folder.

## KUKA robot model and meshes

`assets/robot/kuka_iiwa/` was copied unchanged from `pybullet_data` distributed with PyBullet 3.2.7. Upstream location:

https://github.com/bulletphysics/bullet3/tree/master/examples/pybullet/gym/pybullet_data/kuka_iiwa

The URDF identifies the original xacro source as `https://github.com/rtkg/lbr_iiwa` and preserves the BSD-style two-clause notice for **Robert Krug and Todor Stoyanov, AASS Research Center, Orebro University (2015)**. Original notices remain in the assets; the URDF header is also copied to `third_party_licenses/KUKA_URDF_NOTICE.txt`. See `assets/README.md` for the original project attribution. This project uses the seven-joint KUKA LBR iiwa asset, not a UR5 asset.

Panel, wall, and obstacle boxes are generated by the project code. No standalone Gazebo simulator or ROS stack is included or required.
